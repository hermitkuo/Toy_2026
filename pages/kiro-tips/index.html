規格驅動 Spec

Kiro 的核心：先把 prompt 變成 requirements → design → tasks，再生成程式碼。規劃便宜，重寫最貴。

Spec

先規劃，別急著生

01

能用 Spec 就別純 vibe coding

Vibe coding 適合原型；production code 走 spec-driven，才有文件、稽核軌跡與可維護性。

02

先在 Spec 模式規劃，省實作 credit

設計階段反覆迭代最便宜，避免用錯方向燒掉昂貴的實作 credit。

Tasks 拆細

在 tasks.md 拆成小而明確的任務，agent 越不易走偏，也好逐項驗收。

04

早期就課正方向

走偏立刻 course-correct。放任蓋錯再重寫 = 雙倍 credit 罰款。

05

不是每件事都丟 agent

小改動手打更快。知道何時該自己動手，何時該叫 agent。

Skills · Powers · MCP

Skills

放對位置、寫準描述

15

SKILL.md 要放子資料夾

全域 ~/.kiro/skills/<name>/SKILL.md；丟在根目錄不會被認。

16

description 特別重要

Kiro 只在關鍵字命中 metadata 才載入；描述準不準決定它會不會被叫出。

17

用 Powers 灌 context

按需把領域知識與工具掛到 agent，不讓每個請求塞滿重複脈絡。

14
MCP · Credit

18

接 MCP 拉外部資料源

原生支援 MCP，接 API、資料庫、文件；別硬塞進 prompt。

19

06

建立 Harness

Harness ≠ 從零造 agent。Kiro 已內建 agent loop；你在外圍配 5 層 config，設定產出天花板。

16
Harness

五層架構（由下往上疊）

L0

選模型

Opus 4.8 關鍵 · Sonnet 日常 · Haiku 輕量。/effort 調力度，記 credit 倍率。

L1

Context 管理

/context、/compact、/rewind、# 引用檔。~90% 自動壓縮。

L2

知識與工具

Steering · Skills · Hooks · MCP，全放 .kiro/。

L3

編排

IDE spec 三件套 · CLI /plan · Subagents（CLI 最多 4 並行）。

L4

驗證

生成／評估分離，獨立 review agent。CLI review loop 上限 10。

✦

會腐朽，要維護

模型變強就拆鷹架；保留恆常紀律。每 3–6 個月審一次。

17
Harness

.kiro/ 目錄骨架

.kiro/
├── steering/     product.md (always) · tech.md (fileMatch)
│                debugging.md (auto)
├── skills/<name>/SKILL.md · scripts/ · references/
├── specs/<feature>/{requirements,design,tasks}.md
├── hooks/*.kiro.hook
├── agents/reviewer.md          # CLI 自訂 subagent
└── settings/mcp.json           # 外部工具/API

07

Loop Engineer 自迴圈

兩條路：內建 /goal（最簡），或外掛 Ralph Loop（可審、含自我修正日誌）。

19
Loop · 內建

/goal — 目標驅動迴圈

# 自主 loop：plan → implement → verify → iterate → complete（預設 5 圈）
/goal refactor the auth module to use JWT tokens and ensure all tests pass
/goal --max 10 migrate the test suite from Jest to Vitest
/goal clear   # 取消

關鍵：驗收條件寫死在句子裡。「all tests pass」= 具體；「improve the code」= 模糊會空轉。跑一半可 Ctrl+S queue steering 改方向。

20
Loop · Ralph

Ralph Loop — 逐 task 自我修正

每圈 6 phase

  • 讀 context（steering + spec + progress）
  • 挑一個最小編號未完成 task
  • 實作前先讀過往修正，不重犯
  • 實作＋跑 check，失敗即修即記
  • 對 requirements.md 驗收
  • 更新 progress／timing

跑法

# <圈數> <spec 名>
./ralph-loop-kiro-specs-script.sh 15 auth-feature

# 迴圈本體
echo "$prompt" | kiro-cli chat \
  --trust-all-tools --no-interactive

核心是 progress.md 的 Corrections 區，每圈先讀、禁止重犯。

Kiro vs Claude Code vs Codex

KiroClaude Code / Codex
