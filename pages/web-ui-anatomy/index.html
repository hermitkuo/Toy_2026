UI VOCABULARY · CROSS-FUNCTIONAL

現代網頁 UI 名詞解剖圖 Anatomy of a Modern Web UI — a shared vocabulary for PMs, engineers, and designers

跨職能會議上最貴的誤會，多半不是意見不同，而是同一個詞指的不是同一塊東西。「彈窗」可能是 Modal、Drawer 或 Popover；「改一下 header」可能是指容器高度、導覽項目或品牌區。這頁把一個網頁畫面由上而下拆成 23 格，滑過任一格就看得到該區塊有哪些名詞、可以驗收的檢查要點、以及新手最常犯的失誤。第二分頁收完整的 100 個名詞總表。

畫 面 解 剖 圖

一個網頁由上而下有哪些東西，各自叫什麼

顏色代表元件性質，線型再做一次相同區分（實線＝流程、虛線＝決策分流、點線＝旁支提示），不依賴辨色即可讀。

流程步驟
使用者由上而下必經的畫面區塊：Header → 首屏 → 內容 → 表單 → 頁尾。
決策點
要先回答才知道該用哪個元件的岔路，判準寫在節點副標，不靠品味。
關鍵難點
跨職能最常返工的兩件事：三種狀態沒設計、確認對話框濫用。
旁支・修飾因子
不在主軸上、但會影響整頁的元件群：側欄、浮動層、覆蓋層家族。

關 鍵 難 點

十個一句話就能記住的失誤

把圖上每一格的「關鍵難點」抽出來獨立成卡，適合在設計交付前、或 spec review 前掃一遍。每張卡的標題就是可以直接拿去講的那句話。

狀 態 設 計
設計稿只畫「有資料且正常」的那一張，就是在請工程師自己發明另外三張

每個會載入資料的區塊都要交付四張圖：載入中、空的、出錯、內容過長。缺哪一張，實作時就會出現一個沒人審過的畫面。空狀態還要再分「還沒建立過」與「篩選後無結果」——前者要給建立入口，後者要給放寬條件的建議，兩者的文案完全不同。

表 單
用 placeholder 當標籤，等於在使用者填到一半時把題目收走

Placeholder 只要一開始輸入就會消失。長表單填到第七格回頭檢查，會發現自己完全不記得每格要什麼。Label 必須常駐，而且要與欄位綁定（點標籤能聚焦欄位）。若真的沒有空間，用 Floating Label，不要直接省掉。

動 作 設 計
Undo 幾乎永遠優於「你確定嗎？」

確認對話框會被訓練成無腦點掉，真正的誤刪照樣發生，代價是每一次正常操作都多一步。可逆的動作直接做，配一個停留 5–10 秒的 Undo；只有真正不可逆、且影響他人的動作才值得攔下來，而且該要求輸入名稱確認，不是按「確定」。

元 件 選 型
講「彈窗」而不指名，工程師就會做出另一個

Modal 打斷流程且鎖定焦點、Drawer 與 Bottom Sheet 保留脈絡、Popover 錨定在觸發元素旁、Toast 完全不打斷。選型只看兩件事：要不要打斷使用者、內容是否需要原本的脈絡。需求文件寫「彈窗」，等於把這個決定丟給實作者猜。

內 容 長 度
沒定義最大字數，中文長名稱就會撐爆你的卡片

「這個欄位最長會有多長？」是交付時最常漏問的一句。每個文字欄位都要標最大字數與截斷方式，並決定截斷後能不能看到全文。設計稿裡的假資料通常剛好，正式資料通常不是。

可 存 取 性
outline:none 是一行程式碼，代價是整個鍵盤族群

移除焦點環之後，只用鍵盤操作的人完全不知道游標在哪。不喜歡預設樣式就換一個，不要拿掉。同一組人也依賴另外三件事：Tab 順序與視覺順序一致、Modal 開啟時焦點鎖在裡面、關閉後焦點回到觸發它的按鈕。

色 彩
只用顏色傳達意義，對紅綠色覺辨識障礙者等於沒有標示

紅綠色覺辨識障礙在男性約占 8%。狀態標籤、漲跌數字、必填標記、錯誤欄位——顏色之外一定要有第二個編碼：圖示、文字、線型或位置。這也是為什麼這張圖的四種語義同時用了顏色與線型。

設 計 系 統
13px、17px 這種隨手數值，三個月後會變成幾百個一次性樣式

間距、字級、圓角、陰影都應該來自 token，而不是逐案調整。Token 命名要寫用途（color-danger）而非外觀（red-500），否則改品牌色時你會發現「red-500」被拿去當成功色用了。設計檔與程式碼必須共用同一份定義，不能各維護一套。

導 覽
Tabs 做成流程、Stepper 做成分頁，是同一個錯誤的兩個方向

Tabs 是平行且可任意切換的內容視圖，Stepper 是有先後順序的流程。把結帳做成 Tabs，使用者會跳過必填步驟；把平行內容做成 Stepper，使用者被迫走完才能看第三項。分不清時問一句：跳著看會不會出事？

行 動 裝 置
hover 才看得到的資訊，在手機上等於不存在

Tooltip、hover 展開的 Mega Menu、滑過才出現的操作按鈕，在觸控裝置上都沒有對應行為。必要資訊永遠不能只靠 hover 揭露。同理，觸控目標小於 44×44 pt 在桌機上點得到、在手機上點不到，設計稿的滑鼠游標會騙人。

名 詞 總 表

100 個名詞・完整對照

圖上 23 格是骨架，這張表是完整清單。組別代碼對應同目錄《網頁 UI.md》的 A–H 八組：A 導覽｜B 版面｜C 按鈕｜D 表單｜E 回饋｜F 覆蓋層｜G 資料展示｜H 系統基礎。「最常踩的一件事」每項只留最致命的那個，完整的三項失誤請查 md 檔。

組名詞常見位置最常踩的一件事

品牌標記		Header 左上角忘了讓它可點擊回首頁

漢堡選單		手機版 header 角落桌機版也硬用，把主導覽藏起來降低發現率

側邊導覽		畫面左側，多見於後台階層做到三層以上，使用者記不住位置
AMega Menu
大型下拉選單		頂部導覽展開的大面板用 hover 觸發導致誤觸，行動裝置無替代方案

下拉選單		按鈕或導覽項下方與表單用的 Select 混用命名
